# 设计说明

[← 回到 README](../README.md)

## 一、为什么是「重映射 token」而不是「重写界面」

DSH 的界面是编译产物（`@deepseek-ai/dsh-web-frontend` 的 dist，以及几十个客户端插件包各自内联的 CSS），
改不了源码级组件。但它留了一个正式的口子：整套 `--dsw-*` token 阶梯。
所有官方组件都从这套阶梯取色，所以**重映射它等于重映射整个客户端**——这正是官方主题系统存在的意义
（`@nonamelego/dsh-catppuccin` 走的也是这条路）。

所以这套皮肤的结构是：**一套配色阶梯 + 一层风格样式表 + 一个 CRT 覆盖层**，没有一处碰 React 组件树。

## 二、配色怎么来的

取值不是「照着琥珀色调出来的」，而是直接从片头动画的原稿抄的
（`dsh-550c-boot` 的 `assets/550C-source.html`，以及它 `src/enhance.js` 里那四套配色块）。
理由很直接：**片头播完、界面接手时不能有色相跳变**，否则「同一台机器」的错觉当场就破了。

### 每套方案只有约 20 个原色

```
accent / accentBright / accentDim      主色三档
bg / bgPanel / bgWin / sidebar         表面四档
text / secondary / textDim / textFaint 墨色四档
red / redBright / green / cyan         状态与语义色
```

其余 100 多项从这个原色集推出：

| 组 | 推导方式 |
|---|---|
| 表面 | `layer-1` = `--bg-panel`、`layer-2` = `--bg-win`、`layer-3` 与浮层 = 底与主色混合 |
| 墨色 | 沿一条从 `--text` 走到 `--text-faint` 的坡道 |
| 交互与边框 | 全部是主色的不同透明度（hover 10%、active 18%、边框 14%→42%） |
| 状态 | 直接复用片头的 `--red` / `--green`，于是失败的工具调用与片头的红色告警是同一个红 |
| shiki | 关键字=主色、字符串=绿、函数=青、注释=暗部 |

好处是新增一套配色只要填 20 个数，而不是 200 个。

### 两处对原稿的偏离，都为可读性

1. **`--text-faint` 只用于 1px 细线。** 原稿里 `#4a3f28` 是装饰色（片头拿它画分隔线），
   拿它做界面说明文字会掉到 3:1 以下，所以说明文字用亮一档的值。
2. **正文/次级色的对比度下限。** `test/palette.test.mjs` 会断言正文色对底色与层 1、
   次级色对底色都通过 WCAG AA（4.5:1）。四套方案实测全部通过。

## 三、字形与「仪器感」的词汇

参照 eDEX-UI 的调性——把终端装进一台仪器——但词汇换成 550C 的：

| 元素 | 来源 |
|---|---|
| 等宽字体 `Cascadia Mono + NSimSun` | 片头增强层选定的 Windows 定宽组合（CJK 逐字定宽，混排才对得齐） |
| 全大写 + 字距标签 | 片头的面板标题与 HUD 读数 |
| 方块光标 `▊`（1.06s 阶梯闪烁） | 片头 `#mainBody::after` 的同一拍 |
| 字符格进度条 | 片头 `.wp-prog` 的 4px 格 / 3px 间隔 |
| 角标括线 | 仪器面板的装饰，用八个 1px 渐变画（两两一组四个角）——只有这样才能在任意尺寸下保持锐利，且不和元素自己的边框打架 |
| 方块圆角 | CRT 没有圆角塑料件；但圆形必须保留（头像、状态点、发送键），否则不是复古而是坏了 |
| 磷光辉光 | 用 `text-shadow` / `box-shadow` 而不是投影——CRT 不投影，它发光 |
| 扫描线 / 暗角 / 滚带 / 闪烁 / 顶辉 | 一个 `pointer-events:none` 覆盖层承载 |

### 扫描线的不透明度是负数级的设计决策

`0.32` 的线在 `0.5` 的整体强度下叠加。这个值是照着 **12px 中文的可读性**调的：超过约 0.2 的净效果，
小字号中文会糊成一片。所以「CRT 气氛」这一行给了四档，并且可以整体关掉。

## 四、为什么不加读数栏

第一版做的是「上下两条读数栏 + 仪器模块 + 火花线」——很 eDEX，也很像操作台。
但它**占了 88px 并位移了整个应用**，与「不改布局」的硬约束冲突，所以整套拆掉了。

第二版把 550C 标志放进了对话页右上角的背景里，重演整套开机流程。那版能跑，
但**内容冗余**：47 节点逐个覆写、两处异常、九段阶段列表——那些是片头的戏剧内容，
在一枚角落标志里全是噪音。

## 五、对话框里的 550C

现在的做法：标志住进**对话框（输入框）内部**，工具栏那一行的空档里。

位置不是猜的。`tools/scenarios/composer-map.js` 把输入卡片内部量了一遍：

```
输入行:   y  8..60    x 0..873
工具栏行: y 72..114   x 0..877
  [+] [+] [完全权限]  ...空档 x194..609...  [模型] [发送]
```

权限选择器到模型选择器之间有 **415px 的空档**，标志就居中落在那儿——
读起来像输入舱自带的铭牌，而不是漂在对话里的东西。

内容是**精简过的**：像素 `550C` 逐格写出，然后逐字打两行开机语
（`[550C] 核心在线。` / `[550C] 经典控制单元就绪。`），最后停在 `SYSTEM READY`。
没有覆写流程，没有节点计数。

一条硬约束在这里格外要紧：**输入卡片的高度由它自己的内容决定**，
所以标志必须是绝对定位、`pointer-events:none`。一旦它在流里，整个输入簇就会被它撑大——
`npm run geometry` 就是盯这件事的。

那个「挂载前等待」的 bug 值得记一笔：等待循环原本把「**尚未挂载**」当成了「已销毁」
（输入框在插件 apply 时还没渲染），于是瞬间烧完重试次数并提前退出，动画永远不开始，
而且没有任何报错。修法是让取消判据只管**销毁**，不管连通性。

## 六、状态存在哪

| 状态 | 位置 | 为什么 |
|---|---|---|
| 选了哪套配色 / 气氛 / 等宽 | `$DSH_HOME/550c-skin-state.json` | DSH Desktop 每次启动都换随机端口，浏览器存储按 origin（含端口）隔离，每次都是空的 |
| 同一份的同步缓存 | `localStorage` | 首帧必须同步可读；异步读会让 DSH 原色先闪一下 |
| 主题偏好 | DSH 设置作用域 | 官方通道，但它只接受 `light/dark/system`，第三方主题要自己记住并重新施加 |

「皮肤开不开」的唯一真相是插件自己的 `scheme`，**不是**主题服务的当前主题。
原因是 `ThemeRuntime.adopt()` 每次设置作用域更新都会把第三方偏好倒回内置值，
如果拿服务状态当开关，整套皮肤会跟着来回抖动（HUD 会被反复拆建）。
主题服务只用来做一件事：让 外观 面板高亮到正确的条目。
